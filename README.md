# Windows 操作教程：让现有 ChatGPT 网页会话与现有 Codex 任务自动对话

本仓库只使用 Python 标准库和 Edge 扩展 API；正常运行无需安装 Python 包。适用于 Windows、Edge 中已登录的 ChatGPT 会话，以及已安装并登录的 Codex 桌面应用。源码位于 `bridge.py` 和 `extension/`。

本教程从打开 PowerShell 开始。**请运行本文件夹中的 `bridge.py`，不要运行 `codex resume --all`。** 后者是 Codex 自己的交互界面，复制它的终端内容可能得到工具调用、审批记录等日志，而不是本桥接器的任务列表。

桥接器由两部分组成：

| 名称 | 用途 | 你需要做什么 |
| --- | --- | --- |
| `bridge.py` | 在本机连接所选 Codex 任务，等它完成后取得最终报告 | 在 PowerShell 启动并保持运行 |
| `extension` 文件夹 | 让 Edge 中原有 ChatGPT 标签页读取指令卡片、发送报告 | 在 Edge 中加载一次扩展，再绑定目标标签页 |

完成一次配置后，每一轮不需要手工复制、粘贴、按快捷键或点发送。程序只取标题为「给 Codex 的指令」且有复制按钮的卡片内容，不转发整条 ChatGPT 回复。Codex 只在一轮真正完成、取得最终报告后才回传。

## 0. 开始前确认

1. 打开 **Windows PowerShell** 或 **PowerShell**。在开始菜单搜索“PowerShell”即可。
2. 分别输入以下两条命令，每条输入后按 Enter：

   ```powershell
   python --version
   codex --version
   ```

   第一条应显示 Python 3.10 或更高版本；第二条应显示 Codex CLI 版本。如果 `python` 找不到，可以试 `py -3 --version`，并把本教程后续命令开头的 `python` 换成 `py -3`。如果 `codex` 找不到，先安装或修复 Codex CLI。
3. 确认你要连接的 **Codex 桌面任务当前没有运行中的回复或待处理审批**，且要连接的 **ChatGPT 网页会话已经在 Edge 中打开**。桥接器要求 Codex CLI 支持 `codex queue --thread --message`，启动时会自动检查。

下载或克隆本仓库后，在 PowerShell 进入解压出的 `chatgpt-codex-bridge` 文件夹。下文命令都在该文件夹运行，例如：

```powershell
cd "C:\你的下载目录\chatgpt-codex-bridge"
```

## 1. 先只看 Codex 任务列表（不会启动自动对话）

在 PowerShell 运行：

```powershell
python .\bridge.py --list-tasks
```

正常输出的开头是 **`本机 Codex 普通任务列表（最近 30 条）：`**。每条包含序号、Codex 桌面侧边栏显示的任务名称、方括号中的任务 ID，以及下一行的工作目录。例如：

```text
本机 Codex 普通任务列表（最近 30 条）：
 1. 修复登录页 [12345678-1234-1234-1234-123456789abc]
    D:\projects\my-app
 2. 整理测试 [87654321-4321-4321-4321-cba987654321]
    E:\work\another-app
```

上面两条只是示例。**现在只记住目标任务的序号或名称，不要复制示例 ID。** 脚本优先显示 Codex 保存的任务名称；只有任务确实没有名称时，才明确标成「未命名；首句摘要：…」。旧版脚本曾把首条用户消息误写成“任务标题”，因此你会看到“我想做一个脚本…”那样的长句；现已修正。列表默认只显示普通用户任务，自动化运行、子任务和审批检查记录不会混进来。`--list-tasks` 只读本机索引，不发送消息，也不会保持运行。如果你看到的是 `[25] tool exec call`、`APPROVAL REQUEST`、`Reviewed Codex session id` 等内容，那是 Codex 的对话或审批日志，**不是**这里说的编号列表；请检查输入的命令是否确实包含本文件夹的 `bridge.py --list-tasks`。

“任务”是 Codex 左侧列表中的一条对话，不是 Windows 任务管理器中的程序进程。脚本会按你选择的任务自动找到它的 ID，**不需要你填写 UUID 或工作目录**。列表中的工作目录仅供核对任务；消息按任务 UUID 投递，原任务自己保留项目上下文。即使原目录后来移动，投递时也不需要提供一个目录位置。

## 2. 看现在轮到谁说话，再选择起点

这一步只决定**启动时的第一条消息从哪边来**。两种情况选一种；进入自动循环后，不必每轮重选。

| 现在已经有什么 | 选择 | 绑定后程序先做什么 |
| --- | --- | --- |
| ChatGPT 已经写好带复制按钮的「给 Codex 的指令」卡片 | A | 只把卡片里的指令发给 Codex |
| Codex 已经写好最终报告，ChatGPT 还没收到 | B | 自动读取所选 Codex 任务上一轮的最终报告并发给 ChatGPT |

### A：现在轮到 Codex

Edge 中的目标 ChatGPT 会话**已经给出下一步指令**：它最后一条完整回复里有一张「给 Codex 的指令」卡片，卡片带复制按钮。接下来本来就该把卡片里的指令发给 Codex。

此时选 **A**：第 4 步启动服务、第 5 步绑定后，直接在扩展弹窗点 **「A：从网页现有指令卡片开始」**。程序会读取那张卡片并发给 Codex。你不用复制卡片。请先确认这是你要执行的最新指令，避免重发旧指令。

### B：现在轮到 ChatGPT

目标 Codex 任务**已经完成一轮并给出最终报告**，但 Edge 中的 ChatGPT 还没看过这份报告。接下来本来就该把报告发给 ChatGPT，让它分析并产生下一张指令卡片。

此时选 **B**：第 4 步启动服务、第 5 步绑定后，直接在扩展弹窗点 **「B：从 Codex 最新最终报告开始」**。脚本会按你选择的 Codex 任务，从本机历史索引中查找**最新一轮已完成的最终回答**，自动发到原有 ChatGPT 会话。你不需要复制、粘贴或保存文件。之后 ChatGPT 生成指令，循环自动继续。若最新一轮还在运行，或历史索引里找不到可确认的最终回答，弹窗会显示错误，不会误发上一轮或生成中的文字。

如果你已经手工把报告粘贴到 ChatGPT，并且 ChatGPT 已经生成新的指令卡片，现在就属于 **A**。不要再用 B 重发同一份报告。

`--initial-report-clipboard` 和 `--initial-report-file` 仍保留为特殊情况下的备用输入方式；正常使用 A 或 B 都不需要它们。

## 3. 在 Edge 加载扩展（只需一次）

1. 在 Edge 地址栏输入 `edge://extensions` 并按 Enter。
2. 打开页面上的「开发人员模式」。
3. 点击「加载解压缩的扩展」。文件夹选择窗口中选择本仓库里的**整个** `extension` 文件夹。

4. 扩展列表中应出现「ChatGPT ↔ Codex 本地桥接」。如果 Edge 要求确认扩展权限，请核对它只需要访问 ChatGPT 页面和本机 `127.0.0.1`。加载扩展后，回到**已有的 ChatGPT 会话标签页并刷新一次**，让扩展进入该页面。刷新前确认输入框中没有未发送草稿。

不要新开一个 ChatGPT 会话来代替目标会话。扩展随后会绑定你指定的**当前标签页**。

## 4. 启动桥接器并选择 Codex 任务

回到 PowerShell。现在 A/B 都用**同一条**启动命令；起点稍后在扩展里点按钮选择：

```powershell
python .\bridge.py
```

程序先显示与第 1 步相同的编号任务列表，然后提示 **`输入序号：`**。输入目标任务左侧的数字，例如 `2`，按 Enter。这里不需要输入任务 ID、路径或标题。

选择任务后服务处于等待起点状态，不会立刻向任何一侧发消息。B 的报告只会在第 5 步点 B 按钮后读取；不会读取剪贴板，也不会另存为文件。

成功后，PowerShell 会显示 **`已选任务 ...`**、**`Codex CLI 检查通过 ...`**、**`监听 http://127.0.0.1:8765`** 和一行较长的随机字符，即**桥接令牌**。启动检查会在接收任何指令前验证 Codex CLI 能运行并支持消息队列。令牌是这次运行的本机连接密码，不是你的 OpenAI API Key。不要公开它，也不要关闭这个 PowerShell 窗口。

## 5. 把 Edge 中的原有 ChatGPT 标签页绑定到桥接器

1. 在 Edge 切换到**需要自动对话的原有 ChatGPT 会话标签页**。确保地址栏是 `chatgpt.com` 或 `chat.openai.com`，输入框没有未发送草稿。
2. 点击 Edge 工具栏的扩展图标（拼图图标），打开「ChatGPT ↔ Codex 本地桥接」。
3. 「本地端口」保持默认的 `8765`，除非第 4 步启动时你自己用 `--port` 改过。
4. 把 PowerShell 中显示的**桥接令牌**填入「桥接令牌」框。
5. 「指令卡片标题」保持默认内容；「卡片 CSS 选择器」先留空。这两项只在页面结构识别失败时才调整。
6. 点击 **「绑定当前 ChatGPT 标签页」**。弹窗应显示“已绑定标签页 …”。此后保持该标签页和 PowerShell 窗口打开。
7. 看第 2 步判断的起点，在**同一个扩展弹窗**点 **A** 或 **B** 按钮。A 从网页当前指令卡片开始，B 从所选 Codex 任务的最新最终报告开始。点一次即可；自动循环以后不必再点。需要重新选择起点时，也可以直接再点 A/B，包括处于 `report_ready`、尚有报告待发时；这样会放弃该待发报告并开始新一轮。**A 会重新投递网页当前可见的卡片**，若它已经由 Codex 执行过，重复选择 A 可能重复执行。若 Codex 正在执行，先等当前工作完成。

网页右下角会显示「Codex 桥接」状态。后续循环由程序自动完成。旧版 `--start-from-existing-card` / `--start-from-codex-final` 命令仍兼容；如果使用了旧命令，起点已在启动时决定，不用再点弹窗中的 A/B。

## 6. 如何确认正在正常工作

一次正常循环大致是：

1. ChatGPT 回复完成，扩展找到**一张**标题匹配且带复制按钮的指令卡片。
2. 网页右下角显示「指令卡片已送往 Codex」，PowerShell 显示「指令已投递到原 Codex 任务」。Codex 桌面端的原任务开始运行。
3. Codex 完成后，PowerShell 显示「Codex 最终报告已就绪」。中途生成的文字不会回传。
4. 扩展把最终报告发回**同一个** ChatGPT 标签页，等待它产生下一条完整回复。

如果能识别独立的助手消息，且回复以「任务完成」或「需要人工处理」开头，桥接停止。若最后一条回复确实有多张**内容不同**的可见指令卡片，桥接会保持等待，在扩展弹窗点「查看候选卡片」，核对预览后选择一张发送；不会猜测。其他卡片识别失败、Codex 失败、输入框已有**你自己写的**草稿、发送失败或达到默认 20 轮上限，会停止或在网页右下角显示错误。脚本能识别自己刚填入的报告，并在发送按钮暂时不可用时继续尝试发送，不会把它误判成你的草稿。点击发送后若无法确认 ChatGPT 收到，脚本不会自行再次点击；请用第 7 步的恢复按钮判断。

## 7. 停止、重新开始和常见问题

- **主动停止：** 回到运行中的 PowerShell 窗口，按 `Ctrl+C`。如不再使用，也可在扩展弹窗点「解除绑定」。
- **重新开始：** 重新运行第 4 步的命令；程序每次启动都会生成**新令牌**，所以要重新在扩展里填写并绑定。先确认 ChatGPT 最后一条内容适合所选启动方式。
- **提示报告发送后尚未确认：** 新版扩展会持续核对用户消息及 ChatGPT 的新回复，不会每 2 秒重复报错或自动再次点击发送。打开目标 ChatGPT 标签页看看报告是否已出现在**你的消息气泡**中；若仍无法自动确认，打开扩展弹窗，先点「重新检查 ChatGPT 是否收到报告」。若报告确实已经发出，点「我确认已发送，继续下一轮」；若报告仍停在输入框，或网页里确实没有发出去，点「我确认未发送，重新发送报告」。仅在你目视确认未发送时使用重发，以防页面显示延迟造成重复消息。
- **提示「找到 2 张匹配的指令卡片」：** 新版扩展会排除隐藏副本、嵌套容器和相同正文。更新扩展后，若确实仍有两张不同卡片，打开弹窗点「查看候选卡片」，根据前 120 字预览选择正确的一张。桥接在等待你的选择期间不会自动投递。若旧版桥接已因该错误进入 `stopped`，先在弹窗点 A 重新开始，再查看候选并选择。
- **恢复按钮提示 `Receiving end does not exist`：** 新版扩展会检测页面接收端，缺失时自动注入页面脚本。到 `edge://extensions` 重新加载扩展；Edge 若提示新增 `chatgpt.com` 页面权限，请允许，然后再点恢复按钮，通常不用刷新 ChatGPT 标签页。如果页面本身已经关闭或跳转，先重新打开目标会话并绑定。
- **正在用旧版桥接器处理上述报错：** 可以先只去 `edge://extensions` 重新加载扩展，使用新恢复按钮处理当前报告；此时无需先关闭 PowerShell。若要用新版 A/B 弹窗按钮，需按 `Ctrl+C` 停止旧进程，并按第 4 步重新启动。新版服务允许在待发报告状态直接重选 A/B。
- **`python` 或 `codex` 找不到：** 先按第 0 步检查安装和命令是否可用。
- **出现 `[WinError 2]` 或 `Codex CLI 启动检查失败`：** 新版脚本会先解析 Codex CLI 的完整路径，并检查 `--version` 与 `queue --help`；错误会列出程序路径。核对文件是否存在。也可以用 `--codex "C:\你的实际路径\codex.exe"` 明确指定可执行文件。旧版若已在第 1 轮停止，关闭旧桥接器，按第 4 步重启并用新令牌重新绑定，再点 A；指令未成功送达 Codex 时不要改用 B。
- **没有出现编号任务列表：** 检查运行的是本文件夹中的 `bridge.py`。想只看列表，请运行第 1 步的 `--list-tasks` 命令；不要用 `codex resume --all` 代替。
- **列表中找不到目标任务：** 默认只显示最近 30 条普通用户任务，且不显示已归档任务、自动化运行、子任务和审批检查记录。先在 Codex 桌面应用中打开目标任务，使它成为最近任务，再重试。若任务不在本机索引中，脚本不会擅自猜测目标。
- **提示 `thread-store conflict` / `already has an active writer`：** 这是旧版桥接器调用 `codex exec resume` 时与打开的桌面任务争抢写入权。先按 `Ctrl+C` 停止旧桥接器，确认当前 `bridge.py` 已更新，再按第 4 步启动、选择同一任务并用新令牌绑定，最后在弹窗点 A。该次冲突没有把指令送进目标任务；不要因此选 B。新版使用 `codex queue` 投递到原任务，不会再启动第二个写入者。
- **提示任务正在运行或已有待处理消息：** 桥接器为避免把其他轮次的报告误发给 ChatGPT，会停止；等任务完成、清掉待处理消息后再选择正确起点重新启动。
- **提示等待最终报告超时：** 指令可能已送达且仍在执行。先查看原 Codex 任务，勿直接重复投递；确认其最终状态后按 A 或 B 重新启动。
- **Edge 右下角提示找不到卡片：** 检查 ChatGPT 最后一条回复是否已经完成，卡片是否确实有指定标题和复制按钮。页面结构可能变化；需要针对实际卡片设置 CSS 选择器。本脚本尚未在你的具体卡片 DOM 上做现场校准。
- **提示「指令卡片内容为空」，但卡片正文可见：** 旧版扩展可能只选到标题和复制按钮所在的顶部区域。更新文件后，到 `edge://extensions` 重新加载扩展，再刷新目标 ChatGPT 标签页。若 PowerShell 中的桥接器已显示停止，可直接在扩展弹窗点 A 重新开始；先核对当前卡片确实是尚未送达的新指令。
- **报告已经进入输入框，但没有发送：** 先看右下角的完整提示。若提示发送按钮未启用，脚本会保留自己填入的报告并继续检查按钮，不会重复粘贴。若提示发送后尚未确认，按本节前面的恢复按钮处理。修改扩展文件后，在 `edge://extensions` 点击该扩展的「重新加载」；弹窗会在需要时自动注入新版页面脚本。只有页面本身仍显示异常时才刷新目标 ChatGPT 标签页，刷新前先目视确认报告是否已进入聊天记录。
- **端口被占用：** 可能有另一份桥接器在运行。先关闭旧的 PowerShell 窗口，或启动时加 `--port 8766`，并在扩展里把本地端口也改成 `8766`。

## 技术说明与边界

只有能识别独立的助手消息时，扩展才会根据回复开头的「任务完成」或「需要人工处理」自动停止。若新版页面不再提供可靠的消息作者标记，扩展会搜索 `main` 中的指令卡片，但无法安全地把整页文字当作最新助手回复；这时请手动停止桥接。

本地服务只监听 `127.0.0.1`，扩展通过本次运行的随机令牌连接。脚本从本机 Codex 任务索引读取任务 UUID；方式 B 还会只读地查询本机对话历史，用最新已完成轮次的最终消息作为起始报告。正常轮次调用 `codex queue --thread <UUID> --message <指令>`，再只读地监测该任务新轮次，确认用户消息与本轮指令一致、状态为 `completed` 且存在 `final_answer` 后才把报告转发。目录不参与消息投递。为避免轮次混淆，请勿同时在桌面端或其他程序给目标任务发消息。

ChatGPT 页面和 Codex CLI 版本变化可能影响卡片选择器或事件格式。脚本在不确定是否取得最终报告时会停止，不会把流式中间文字当成报告。除首次准备起始内容外，正常轮次无需人工操作。

若新版 ChatGPT 页面不再标明消息作者，扩展会在 `main` 中寻找严格匹配的指令卡片：B 循环会先把发送报告前已存在的卡片记为历史，只自动投递最新一张未处理卡片；选择 A 起点时，则以当前可见的最新卡片作为起始指令。没有新卡片时继续等待，不会用宽松的全页匹配自动投递。弹窗「查看卡片」仍可供核对。桥接器还会拒绝把带有报告固定格式的内容当作指令。报告发送后，扩展需要找到新用户消息或报告在对话区新增的证据才自动确认；证据不足时使用弹窗中的恢复按钮目视核对，避免旧报告造成误确认。

网页右下角状态条同时显示当前桥接阶段、最近一次弹窗按钮操作及其时间、最近一次连接检查时间。点 A/B、查看或选择卡片、恢复报告等按钮时会立即显示“正在处理”，完成或失败后保留结果。更新扩展文件后，在 `edge://extensions` 重新加载扩展，并刷新已绑定的 ChatGPT 标签页以加载新页面脚本。

如果状态条显示 `Extension context invalidated`，说明扩展已重载而该 ChatGPT 标签页仍运行旧页面脚本。先确认输入框没有未发送草稿，再刷新这个标签页并重新绑定；无需重新投递已执行的指令。新版页面脚本遇到该错误会停止旧轮询，弹窗也会提示刷新，而不会在同一页叠加注入另一份脚本。

新版页面没有用户消息标记时，扩展会比较发送前后报告片段在对话区的可见文本和 DOM 文本中出现的次数，并要求输入框已清空，才自动确认发送。若消息被折叠，可见文本不含正文时仍可用 DOM 文本确认。升级前已处于“发送已触发，但仍未确认”的旧轮次没有新版发送前基线；若已目视确认报告出现在 ChatGPT 消息中，在弹窗点「我确认已发送，继续下一轮」，不要点重发。

### 自动操作记录

桥接器运行时，扩展和桥接器的操作事件会自动追加到本项目的 `logs/bridge.jsonl`。弹窗的「查看最近操作记录」可读取最后 100 条；维护者也可直接读取此文件，无需每次手动导出。每条记录有服务会话编号；扩展离线事件补写时还保留原发生时间。扩展在本地服务暂时不可用时，最多暂存 1000 条事件，连通后再补写。日志达到约 5 MB 时轮转为 `bridge.jsonl.1`。记录包含阶段、控件数量、长度和错误类别，不含桥接令牌、指令正文或报告正文。日志目录默认被 Git 忽略；分享日志前仍请自行检查内容。

在仓库根目录运行：

python -m unittest -q test_bridge.py
node test_card.js
node test_popup.js
